## Recommendation

**Build a headless G4 Leto self-play generator: persistent workers, one whole game per worker, two independent player states per game, immutable model data decoded once, on the reference single-pass `rank()` policy, from a declared start-position corpus. Then remove the engine's measured waste in two classes (exact and tolerance), and run a host comparison between the TypeScript/WASM port and the Python reference. Migrate the website separately, with runtime-bound identity. Make the ten deities ten styles on full-strength Leto, with difficulty as a separate, optional axis.**

Martim stated in this conversation that plans exist to reach **maximum theoretical gains**. The plan therefore does not stop at the safe first step. It orders the levers by expected size, keeps every one of them, and gates each by evidence:

1. **Parallel games across all cores.** Games are independent, so this is the largest lever that cannot change a decision if state is isolated (D3).
2. **Exact engine waste removal.** Decode tensors once, skip `predict()` in self-play, keep native state incremental, and evaluate the network sparsely and in batch **with the same accumulation order**, so results stay bit-identical (D5).
3. **Host choice.** The reports put the Python reference at 0.066 s per decision against 0.285 s for the Node port (attributed, uncontrolled). The Python reference is also the quality anchor. It enters the host comparison (D4).
4. **Ceiling track.** Native decision core, SIMD that changes summation order, and cross-game batched inference on the GPU. Each changes numerics or reopens parity, so each needs the tolerance gate and Martim's acceptance (D6).

Decisive reasons:

- **The engine is deterministic.** `rankPosition` has no random draw: ties break by index (`g16v2.ts:34, 346`), and the opening book is a fixed lookup. Leto against Leto from one start position therefore repeats the same game. A games/s figure on one start is worthless as data. The workload must be a **start-position corpus** with both colours per start (D2). Sonnet and normal raised this; I verified it in the code.
- **The website path is not the self-play path.** `searchLetoUntil` runs escalating passes under a 5 s deadline, starting with a shallow pass, and the controller can return the first legal move as a fallback (`letoTimedSearch.ts:184-206`, `letoThinking.ts:115-133`). The parity report measured single-pass `rank`. Self-play uses single-pass `rank()` with the checkpoint budgets (D1).
- **The interactive worker cannot run self-play as is.** It creates a new player whenever the requested side changes (`leto.worker.ts:27-31`), and its calibration key is model revision plus game id, without colour (`letoThinking.ts:118`). Alternating colours through it would reset Leto's state every move. Astra raised this; it is verified.
- **The baseline must be reconciled first.** The parity report names manifest revision `81a597cc…` (`RESULTADOS-LETO.md`, «Exportação e configuração»). The supplied `leto.json` and `leto-version.json` name `bc095e95…`, and `leto.json` carries `pawn_version: 3` and `pawn_proofs`, which the report's configuration list does not mention. Historical parity therefore does not cover the current manifest (D1).
- **The native provenance file names the G16 binaries.** `native-provenance.json` lists `wasm_sha256 520ea10c…` and `loader_sha256 a60e11c2…`, which `leto-work/audit.json` records as `g16-rules.wasm` and `g16-rules.mjs`. `leto.json` names `g4-rules.wasm 48b810e5…` and `g4-rules.mjs 4bc7f79b…`. Identity checks must use the manifest and the fetched bytes, never that file (D7). Sonnet raised this; it is verified.

## Architecture and operation

```
start-position corpus ──► scheduler ──► N persistent workers (N from the sweep)
                                          │  one game at a time:
                                          │   board + history (incremental native state)
                                          │   White player state │ Black player state
                                          │   shared immutable tensors, book, proofs
                                          ▼
                         independent legal replay (python-chess) ──► recorder (JSONL, durable)
                                                                         │
                                         counted games / wall time ◄─────┘
```

- **Engine core** (`G16Network` decision procedure, unchanged in order of operations) is shared by every host.
- **Self-play driver** calls `rank(board, side)` without limits for each side in turn, then pushes the move. It never calls `predict()`.
- **Website adapter** keeps `LetoThinker` and the timed policy, for one human game, with the identity binding of D7.
- **Hosts** (D4) plug the same driver into Node workers, browser workers or the Python reference.
- **Pantheon layer** (D8) sits after `rank()`, in the website adapter only. It never enters the self-play benchmark.

## Material dissent and decisions against prevailing positions

- **Against all three reviews, on the role of paired strength games for exact changes.** The reviews want paired games before accepting any change. For a change whose every decision, utility and spread equals the unchanged engine on the whole benchmark corpus, a match against the anchor replays the same games and cannot discriminate. The plan keeps the paired games (Stage 4, on the integrated generator, as R2 asks) but makes the corpus-wide state comparison the actual gate for the exact class. Paired games are the gate for the tolerance class.
- **Against sonnet's classification of the sparse first layer as numerics-changing.** Done in the original index order, it only removes exact-zero terms. The plan puts it in the exact class, subject to the bitwise corpus test.
- **For sonnet against the prevailing silence, on Python.** The other proposals do not consider the Python reference as a generator. It is the quality anchor and, by the attributed figures, faster per decision. It enters the host race (D4).
- **Single-source findings, verified and adopted:** astra's worker side-reset and colourless calibration key (E6, E7); sonnet's native-provenance mismatch (E15); sonnet's and astra's manifest-revision mismatch (E1); sonnet's determinism point (E3).

- **Style versus ladder.** Sonnet alone proposes a strength ladder. The plan does not reject it by count; it waits on U3 because it weakens Leto for nine levels without an accepted tolerance.
